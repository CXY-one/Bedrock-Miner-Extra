# Bedrock Miner Extra

**[English](README.md) | [简体中文](README_zh-CN.md)**

Fabric **纯客户端**模组：在生存模式中利用原版"无头活塞"特性（Mojang bug **MC-27056**）破坏基岩——**不需要急迫效果、不需要高等级镐**，普通速度挖活塞即可。内置**自动模式**：左键点击基岩即可自动放置活塞+拉杆并破基岩，带缓存队列（上限 5 个位置）。

**支持版本**：26.2 / 26.1 / 26.1.2、1.21.11 / 1.21.1 / 1.21、1.20.6 / 1.20.5 / 1.20.1（Stonecutter 多版本构建，一套源码）。

> 本 mod **不修改任何原版特性**：不直接破坏基岩、不改方块属性；只是自动完成"同一刻内切断信号 + 放置朝向基岩的新活塞"这个人类做不到的 tick 级操作，基岩破坏完全来自原版 bug。

## 特点

- **纯客户端**：只运行在客户端，服务器无需安装；单机、自建服、远程服务器均可使用（mod 只向服务器发送模拟玩家操作的网络包）。
- **不限挖掘速度**：空手慢慢挖、瞬间破坏（效率V 镐 + 急迫II）都可以——mod 在 `MultiPlayerGameMode.destroyBlock` 入口统一处理，慢速进度满与瞬间破坏特判两条挖掘路径都覆盖。
- **自动模式**（`/bedrockMinerExtra auto`）：左键点击基岩自动在其旁边放置活塞+拉杆并破基岩；带 5 个位置的缓存队列，范围外先入队、范围内优先处理。
  - **被挡自动换位**：活塞放置位置被玩家挡住时，自动寻找其他可放置的面，而不是直接失败；
  - **拉杆精确放置**：优先附着在要破的基岩上（充能基岩→100% 激活活塞），其次活塞侧面；附着面由点击位置精确决定，不再受服务器视角延迟影响；
  - **成功后自动清理**：破掉基岩后，自动挖掉已无用（周围没有基岩 / 无法伸出）的残留活塞和拉杆。
- **可开关**：用 `/bedrockMinerExtra` 指令随时开/关（也支持 `/bedrockMinerExtra on|off`），状态保存到 `config/bedrock-miner-extra.json`；开启/进世界时聊天栏提示 `Bedrock Miner Extra 已启动！`，在联机服务器使用时额外提示先征询其他玩家意见。**两个开关联动**：关闭主开关会同时关闭自动模式；开启自动模式会自动打开主开关（自动模式依赖手动流程）。
- **可破方块白名单**：默认只有基岩；可用 `/bedrockMinerExtra blockWhitelist add <方块名>` 加入其它方块（同样方法破）、`remove` 删除、`list` 查看。
- **提示在物品栏上方**：破基岩成功、空间不足、破基岩失败等提示都显示在 **action bar**（物品栏上方，同原版睡眠提示），不刷聊天栏。

## 使用方法（重要：活塞头不能朝基岩）

1. **放置活塞**：放在基岩**旁边或上下任意一面**，但**活塞头必须朝向空气**（活塞能被充能后正常伸出）。活塞头被基岩挡住是**无法**破基岩的。
2. **充能**：拉杆放在活塞**旁边**（侧面、底面都可以，只要能让活塞充能伸出；不要放活塞顶面，也不必附着在活塞上）。
3. **挖掉活塞**（任意速度，包括瞬间破坏——效率V + 急迫II 的镐子也能正常触发）。
4. mod 在挖掘完成前的一瞬间自动：**先瞬间取消充能**（关掉拉杆，让活塞处于失去信号的状态）→ 再在活塞原位放置一个**朝向基岩**的新活塞 → 服务器同一刻处理 → 原版无头活塞特性触发，**基岩被破坏**（无掉落）。

```
示例：破下界顶部基岩（站在基岩层下方）
  [基岩][基岩][基岩]        ← 要破的基岩层
  [ 活塞→][拉杆]            ← 活塞头朝水平（空气，能伸出），拉杆放活塞旁边
  挖掉活塞 → mod 原位放一个头朝上（指向基岩）的活塞 + 关拉杆 → 基岩破
```

## 自动模式

开启 `/bedrockMinerExtra auto` 后，**左键点击基岩**（白名单方块）即可自动破基岩：

1. 检测基岩旁边有没有可用的装置：**已有可伸出的活塞**（头朝空气）会直接复用（不再放新活塞）；活塞旁边**已有能充能的拉杆**也会直接复用（按开关状态自动开启/直接使用，不重复放置）。没有才放新的：优先在基岩旁（靠近玩家的方向）找能放"可正常伸出的活塞 + 拉杆"的位置；都没有则提示**空间不足，无法破基岩**。
2. 自动放置活塞（活塞头朝空气；先发视角包等 1 tick 再放置，保证服务器推导的朝向正确）+ 拉杆（**优先附着在要破的基岩上**——拉杆充能基岩→100% 激活活塞；其次附着在活塞侧面；放置后自动**开启拉杆**激活活塞）→ 等待活塞伸出。
3. **若选中的活塞位置被玩家挡住放不了，自动换到其他面继续尝试**，不会直接失败。
4. 切到快捷栏中**对活塞挖掘速度最高**的工具（26.x 无镐类，按实际挖掘速度选），挖掉活塞 → 复用上面的手动机制（自动断电 + 放新活塞）→ 基岩被破坏。
5. **破基岩成功后自动清理**：mod 自己放置的活塞如果周围已没有基岩（或无法伸出）、以及残留的拉杆，都会被自动挖掉，不堆积。
6. 若热栏缺少活塞/拉杆/挖掘工具，会在物品栏上方提示并跳过。

**缓存队列**（上限 5 个位置，FIFO，满则删最旧的）：点击**范围外**的基岩先入队，玩家靠近后自动处理；点击**范围内**的基岩优先处理（插到队首）。**关闭自动模式会自动清空队列**。每次消耗活塞×2（布置 1 + 替换 1）和拉杆×1（残留会被自动回收）。

## 触发条件（全部满足才生效）

- 被挖掉的是**普通活塞**（粘性活塞不触发）；
- 活塞头方向是**空气**（活塞能伸出）；
- 活塞**旁边任意一面**存在**基岩**（新活塞将朝向它）；
- 活塞当前**处于充能状态**，且充能源是附近（2 格内）的**拉杆**（拉杆在挖掘完成前被关闭，保证新活塞放置时已断电）；
- 玩家**热栏或副手有活塞**（mod 自动切到活塞槽，或直接用副手放置）。

## 指令

```
/bedrockMinerExtra                    开关切换（ON/OFF）
/bedrockMinerExtra on | off           显式开/关
/bedrockMinerExtra auto               自动模式开关切换
/bedrockMinerExtra auto on | off      自动模式显式开/关
/bedrockMinerExtra blockWhitelist add <方块名>   添加可破方块（如 obsidian、minecraft:obsidian）
/bedrockMinerExtra blockWhitelist remove <方块名> 移除
/bedrockMinerExtra blockWhitelist list           查看白名单
```

方块名支持 `bedrock` 简写（自动补 `minecraft:` 前缀）或完整 ID `minecraft:bedrock`；未知方块会提示错误。白名单持久化在 `config/bedrock-miner-extra.json`。

## 已知限制

- 竖直方向（基岩在活塞正上/正下方）100% 稳定；水平方向（基岩在活塞侧面）通过"提前发送视角包"解决 yaw 延迟——**自动模式**在挖活塞前预发视角（放置活塞/拉杆时也是先预发再放）；**手动模式**在你瞄准活塞时预发（瞄准期间服务器视角会临时朝向基岩，准星离开后自动恢复，此时若右键放方块朝向可能受影响）。自动模式的**拉杆附着面**由点击位置精确决定，不再受该延迟影响。
- 破基岩后请**松开左键**：mod 会在放置新活塞后自动保护它约 0.1 秒（2 tick，拦截原版二次挖掘——瞬间破坏+副手场景不会再误挖新活塞），但保护窗口过后持续按住仍可能被原版挖掉。
- 若热栏和副手都没有活塞，mod 会跳过（日志警告），基岩不会被破坏。
- **不支持红石火把充能**：headless 特性要求"先断信号再挖活塞"，但火把只能靠挖掘包破坏（会重置服务器挖掘进度，普通速度下活塞无法同 tick 破坏），协议层无法实现；请使用拉杆充能。
- 依赖原版 MC-27056 特性：若未来 Mojang 修复该 bug，本 mod 将失效。

## 开发

环境：JDK 26（`gradle.properties` 中 `org.gradle.java.home` 指向 `C:/Program Files/Java/jdk-26.0.2`）、Gradle wrapper 9.5.1。

```bash
./gradlew build   # 编译打包（产物在 versions/<版本>/build/libs/bedrock-miner-extra-*.jar）
```

版本锁定：Minecraft `26.1.2` + Fabric Loader `0.19.3` + Fabric API `0.155.2+26.1.2` + Loom `1.17-SNAPSHOT`。

## 代码结构

- `BedrockBreaker` — 纯客户端核心：判定触发条件（活塞能伸出 + 旁有基岩 + 带电）、发包序列（断信号 → 挖活塞 → 放置朝向基岩的新活塞）；
- `AutoBreaker` — 自动模式：左键点击白名单方块入队，客户端 tick 状态机自动"找位置 → 放活塞+拉杆 → 等伸出 → 挖活塞"，复用 `BedrockBreaker` 的 headless 流程；包含被挡换位、放置缓存与成功清理；
- `MultiPlayerGameModeMixin` — 时序钩子：在 `MultiPlayerGameMode.destroyBlock` 入口（慢速进度满与瞬间破坏特判两条路径都经过）先"断信号"并捕获场景，再在破坏包（`START`/`STOP_DESTROY_BLOCK`）发送之后紧跟"放新活塞"的包，保证服务器同刻按"断信号 → 挖活塞 → 放新活塞"处理；还拦截新活塞保护窗口内的二次挖掘；
- `EntityAccessor` / `MultiPlayerGameModeAccessor` — 26.1.2 私有化字段（视角、挖掘目标/进度）的访问器。

## 多版本构建（Stonecutter）

本项目用 **Stonecutter** 维护多版本：一套源码，`//? if` 条件化版本差异，按版本生成并构建。

- **构建指定版本**：`./gradlew :<版本>:build`，如 `./gradlew :1.21.11:build`、`./gradlew :26.2:build`
- **构建当前 active 版本**：`./gradlew build`（active 版本 = `stonecutter.gradle.kts` 中 `stonecutter active "26.1.2"`）
- **版本列表**：`versions.json`；各版本依赖（fabric-api 等）在 `stonecutter.properties.toml`
- **产物**：`versions/<版本>/build/libs/bedrock-miner-extra-<版本号>+<MC版本>.jar`
- **切换开发版本**：改 `stonecutter.gradle.kts` 的 `stonecutter active "..."` 与 `versions.json` 的 `"vcs"`

> 编译要求：Java 25（26.x 目标）/ Java 21（1.20.5~1.21.x）/ Java 17（1.20.1）；本项目 `gradle.properties` 已指定 `org.gradle.java.home`。
